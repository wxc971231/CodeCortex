# Core runtime logging

CodeCortex emits structured JSONL lifecycle events to stderr by default. MCP
stdout remains exclusively protocol frames. The default `CODECORTEX_LOG_LEVEL`
is `INFO`; `DEBUG` adds internal timings and CLI command spans, and `OFF`
disables structured telemetry. Existing CLI diagnostics and third-party MCP
logging remain separate and can also appear on stderr; they are never copied
into the structured file sink.

To collect a debugging session from the contributor Conda environment:

```bash
conda activate codecortex-dev
export PYTHONPATH="$PWD/src"
export CODECORTEX_LOG_LEVEL=DEBUG
export CODECORTEX_LOG_DIR="$(mktemp -d /tmp/codecortex-debug.XXXXXX)"
codecortex validate --json
```

`PYTHONPATH` must point at the worktree being tested when an editable install
points at another checkout. For a Codex-launched MCP process, set the environment
in its registration (using an absolute directory outside the source repository):

```toml
[mcp_servers.codecortex.env]
CODECORTEX_LOG_LEVEL = "DEBUG"
CODECORTEX_LOG_DIR = "/tmp/codecortex-task-20260907/logs"
```

Restart the MCP process after changing its environment; a running process does
not poll configuration. Main creates missing directories with mode `0700` and
files with `0600`. An existing final log directory must already be owned by the
current user with mode `0700`. Relative paths, `..`, symlink components, unsafe
files and unusable permissions cause a safe fallback to stderr. Analyzer always
uses stderr, including during CLI composition/startup and even when it inherits
`CODECORTEX_LOG_DIR`; it never creates a log directory or file. Capture Analyzer
stderr using the host's process diagnostics if needed.

Main files are named `codecortex-<pid>-<random>.jsonl`. Each process/configuration
keeps one active file of at most 5 MiB and three rotated backups (`.1` newest),
at most 20 MiB total. Rotation is thread-serialized, uses private directories
and no-follow file handling, and never shares a file between processes.
Retention is **per process**, not a directory-wide quota: logs from older
processes remain until you remove their disposable task directory. A broken
file sink produces one metadata-only `LOG_SINK_UNAVAILABLE` warning on stderr
and subsequent events use stderr without changing the operation result.

For a running Main process, select its current file and inspect timings:

```bash
tail -F "$CODECORTEX_LOG_DIR/codecortex-<pid>-<random>.jsonl" |
  jq --unbuffered 'select(.event == "success" or .event == "error") |
    {name, event, operation_id, duration_ms, metrics}'
jq -s 'map(select(.duration_ms != null)) | sort_by(.duration_ms) | reverse | .[:20]' \
  "$CODECORTEX_LOG_DIR"/*.jsonl*
```

Every record has `schema_version: 1`, UTC `timestamp`, `pid`, `profile`,
`operation_id`, `span_id`, `parent_id`, fixed `name`, `event`, `level`, and
allowlisted `metrics`. Completed spans add monotonic `duration_ms`. Each MCP
tool call starts a fresh root operation, including sequential calls in one
STDIO session. Internal spans inherit its operation and parent span; concurrent
async tasks do not share mutable correlation state. These IDs are generated by
Core and are not Codex session IDs or MCP JSON-RPC request IDs. Hard process
termination can leave a start event without a terminal event.

Coverage at INFO: all 21 Main / 13 Analyzer MCP tools and startup, Fact Sync,
Preflight, proposal creation/apply, baseline advance, guarded query entry points,
and discussion/follow-up route selection when that planner is invoked. At DEBUG:
CLI command outcome/exit code; Fact Sync source snapshots, parsing, retry markers,
database commit and full replacement; Preflight retry markers; recovery checks,
rebuilds and bootstrap recovery; formal graph/baseline commits; proposal cache
refresh. Nested timings overlap; do not sum parent and child durations. Lock
waiting is included in the enclosing operation and is not separately sampled.

Metrics include validated source digests and graph/index coordinates, parsed and
changed file counts, retry count, scope confidence, route, query truncation and
returned context counts. Cache warnings and diagnostics contribute counts only.
Failures record error class and stable domain code where available, never the
exception message. CLI command spans report a nonzero exit as an error. Query
truncation reports what Core actually returned; it does not imply full graph
coverage. Result selectors are explicit; unsupported metadata is dropped.

Logs are disposable diagnostics, excluded from formal state, source facts and
source digest calculation (`.jsonl` is not managed Python source). Keep the sink
outside the repository so it is also absent from ordinary Git workflows. Logs
do not contain byte-for-byte source files, prompts, answers, approval text,
arbitrary arguments/results, environment variables, credentials or exception
tracebacks. This traces observable Core work only; it cannot trace Codex private
reasoning, internal model execution, or editor-host activity. Standard existing
CLI error output and third-party stderr diagnostics are outside this JSONL
privacy boundary.
